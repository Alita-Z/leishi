# 职能沟通翻译助手

这是一个帮助产品经理和开发工程师更好理解彼此语言的AI翻译助手。它可以将产品需求翻译成技术语言，或将技术方案翻译成业务语言。

## 功能说明

1. **产品 → 技术翻译**：将产品经理的业务需求转换为开发可理解的技术说明
2. **技术 → 产品翻译**：将开发的技术方案转换为产品可理解的业务价值
3. **流式输出**：实时展示翻译结果，提供更好的用户体验

## 快速开始

### 安装依赖

```bash
pip install -r requirements.txt
```

### 配置API密钥（可选）

复制 [.env.example](.env.example) 文件为 `.env` 并填入你的 OpenAI API 密钥：

```bash
cp .env.example .env
# 然后编辑 .env 文件填入你的API密钥
```

如果不配置模型相关信息，系统会使用模拟数据进行演示。

### 运行项目

```bash
uvicorn app:app --reload
```

访问 http://localhost:8000 查看应用。

## 测试用例

### 产品 → 技术翻译示例

**输入（产品视角）**
```
我们需要一个智能推荐功能，提升用户停留时长
```

**翻译给开发（输出示例）**
```
推荐采用协同过滤算法实现推荐功能。数据源需要用户行为日志和商品信息表。要求支持实时推荐，响应时间不超过200ms。需要开发推荐引擎、数据处理模块和缓存机制。预计开发周期为10人日。
```

### 技术 → 产品翻译示例

**输入（开发视角）**
```
我们优化了数据库查询，QPS提升了30%
```

**翻译给产品（输出示例）**
```
数据库查询优化将显著提升用户页面加载速度，改善用户体验。此优化可支撑用户量增长30%，同时降低服务器成本约15%。无业务风险，可直接上线。
```

## 提示词设计说明

### 角色区分设计

为了让AI更好地理解产品经理和开发工程师的不同视角，我设计了两套不同的提示词：

1. **产品 → 技术**：
   - 强调技术实现细节（算法、数据源、性能指标等）
   - 要求补充最佳实践建议
   - 输出结构化的技术说明

2. **技术 → 产品**：
   - 强调业务价值（用户体验、业务目标、成本效益等）
   - 要求主动推断业务影响
   - 输出易于理解的业务语言

### 关键设计点

1. **明确指令**：清楚告诉AI它的角色和任务
2. **结构化输出**：指定输出格式和必须包含的内容要点
3. **主动补充**：即使原始输入缺少某些信息，也要求AI基于最佳实践主动补充
4. **避免冗余**：要求直接输出结果，不要添加解释性前缀
